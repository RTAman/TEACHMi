# C 문제 API

POST /api/v1/sessions/{sessionId}/problems는 학습당 두 문항을 한 번 저장합니다.
GET /api/v1/sessions/{sessionId}/problems/{problemId}로 같은 문항을 복원합니다.
로그인 쿠키가 필요하고 POST는 X-CSRF-Token도 필요합니다. 정답·해설·채점 기준은 응답에 없습니다.

## 실제 Gemini 생성과 비활성 상태

GEMINI_ENABLED=true와 유효한 키·모델이 설정되면 GeminiProblemGenerator의 v5 프롬프트로 실제 원문 기반 문제 2개를 생성합니다. A의 소유권/선택 개념과 B의 학습 근거를 확인하고 공통 포트·CitationRules를 통과한 결과만 저장합니다. 비활성 상태에서 데모도 꺼져 있으면 503 ASSESSMENT_GENERATION_PENDING을 반환합니다.

v5는 소유권 검증을 마친 선택 원문에서 만든 6~40자의 정확한 인용 후보를 사용합니다. 모델에는 후보의 출처 ID와 인용문을 한 쌍으로 복사하도록 지시하며, 응답 스키마의 인용 enum·40자 상한과 서버의 ID/인용 쌍 검사를 함께 적용합니다. 원문·AI 응답을 잘라 맞추거나 CitationRules를 완화하지 않습니다. 후보는 조각당 최대 8개·전체 최대 64개이고, 후보가 없으면 예약·호출 전에 LEARNING_SOURCE_INCOMPLETE로 중단합니다. 이 검사는 인용의 정확성을 보장하는 기계적 검사이며 문제의 의미적 품질까지 보장하지는 않습니다.

동일 입력·설정의 기존 v4 성공 캐시는 현재 소유권·정확한 원문·기존 C 규칙을 다시 검사한 뒤 읽기 전용으로 복원할 수 있습니다. 기존 성공·실패·uncertain 원장을 변경하거나 v4 요청을 재호출하지 않습니다. v5를 적용해도 unresolved 호출이 있는 세션의 신규 생성은 차단됩니다. 기존 failed 기록을 운영자가 임의로 초기화하거나 버전을 바꿔 재시도하는 절차를 추가하지 않습니다. 생성 실패의 자동 재호출도 없습니다. 채점도 아래 v5의 짧은 인용 후보를 사용하며 판정 기준은 유지합니다.

명시적으로 ASSESSMENT_DEMO_ENABLED=true를 설정하면 개발·시연용 고정 감가상각 문항을 사용합니다.
이는 강의자료나 개념을 반영하지 않는 데모입니다. 데모 문항의 source_chunk_ids는 빈 목록이며
임의의 강의자료 출처를 붙이지 않습니다. 실제 생성기와 채점기를 연결하기 전 일반 운영에서 켜지 마세요.
이미 저장한 문항은 설정을 꺼도 소유자에게 조회·재호출로 같은 문항을 반환합니다.

타임아웃·미확인 호출은 공통 원장을 보존하고 재생성을 차단합니다. 오류 응답의 recovery와 [공통 Gemini 정책](GEMINI_CONTENT.md)을 따릅니다.

## 저장 일관성

생성은 DB 잠금 밖에서 수행합니다. 저장 직전에 같은 트랜잭션에서 B의 회원 잠금 → 소유 세션 잠금을 취득하고
active/problem, 세션 버전, 진행 중 대화·재설명·미확인 문항 복귀가 없는지,
저장된 최초 wrapup 답변이 실제로 해당 학습에 속하는지 재검증합니다.
생성 중 학습이 교체되거나 버전이 바뀌면 409이며 문항을 저장하지 않습니다.
동시 생성 요청은 같은 문항 두 개로 수렴합니다. 저장 오류를 성공 응답으로 숨기지 않습니다.

V1~V9 마이그레이션과 B HTTP 응답 형식은 변경하지 않습니다.
재설명 대상 조회·해설·리포트·학습 종료의 C 어댑터를 실제 저장 기록에 연결했습니다.

## 첫 답안 제출

POST /api/v1/sessions/{sessionId}/problems/{problemId}/attempts

로그인 쿠키, X-CSRF-Token, Idempotency-Key가 필요합니다.
JSON 본문은 answer(공백 제외 필수, 최대 2,000자), work(공백 제외 필수, 최대 4,000자)입니다.
응답은 최초 제출과 성공 재전송 모두 201이며 Cache-Control: no-store를 반환합니다.

```json
{"answer":"200만 원","work":"잔존가치를 뺀 원가를 사용 기간에 나눕니다."}
```

성공 응답은 attemptId, problemId, attemptNo, judgement, availableActions, nextProblemId입니다.
정답·해설·채점 기준·원래 풀이 내용은 응답에 포함하지 않습니다.
정답은 문항을 확정하고 next_problem 또는 finish_problems를 반환합니다.
앞 문항이 확정되기 전 다음 문항의 제출은 409 PREVIOUS_PROBLEM_REQUIRED입니다.
오답은 문항을 확정하지 않고 reteach·view_solution 이름을 반환합니다.
이 두 동작은 아래 재설명·해설 API로 연결합니다.
pending_review는 오답으로 집계하지 않으며 next_problem 또는 finish_problems로 진행합니다.

회원별 키 공간에서 세션·문항·답·풀이의 SHA-256 요청 지문을 검증합니다.
같은 키·같은 본문은 DB의 동일한 첫 답안·판정을 복원합니다. 이후 문항 진행이나 학습 중단 뒤에도 같은 결과입니다.
같은 키에 다른 본문·대상은 409 IDEMPOTENCY_KEY_REUSED이고,
첫 시도 뒤 새 키로 제출하면 409 FIRST_ATTEMPT_ALREADY_SUBMITTED입니다.
재설명 후 재시도 API를 추가할 때도 이 첫 독립 답안을 변경하면 안 됩니다.

새 제출은 B의 같은 회원 → 세션 잠금 안에서 소유권·최신 상태·문항 근거 버전을 확인합니다.
이미 읽은 B 엔티티도 잠금 후 refresh하여 오래된 상태로 판정하지 않습니다.
답안 저장·판정 저장·정답 문항 확정은 하나의 DB 트랜잭션입니다.
동시 같은 키는 한 결과로 수렴하고 다른 키의 중복 첫 시도는 거절합니다.
원격 채점 실패 시 입력 답안은 미판정으로 보존됩니다. 같은 키·본문으로 재접근하며 recovery가 허용하는 경우에만 명시적으로 재시도합니다.

Gemini 활성 시 GeminiAnswerGrader의 v5 프롬프트로 답과 풀이를 실제 채점합니다. 입력 저장/커밋 → DB 잠금 밖 AI 호출 → 최신 상태 검증/판정 저장으로 분리합니다. correct/wrong/pending_review 판정 기준과 출처 1개·ID당 evidence 1개·6~40자 정확 인용 규칙은 유지합니다. 비활성 상태에서 데모도 꺼져 있으면 ASSESSMENT_GRADING_PENDING입니다. 명시적 데모의 FixedAnswerGrader는 의미 기반 채점이 아닙니다.

v5 채점은 문제 생성과 같은 SHORT_EXACT 포트 정책을 사용합니다. A가 소유권을 확인한 실제 선택 원문에서 만든 인용 후보를 모델에 제공하고, 생성 스키마의 인용 enum·40자 상한 및 서버의 출처 ID/인용 쌍 검사로 검증합니다. 판정을 강제하거나 모델의 인용을 잘라 맞추지 않습니다. 기존 v4의 지시·스키마·입력 및 STANDARD 요청 형식은 보존하며, 동일 attemptId·답안·풀이·문항·설정의 유효한 v4 성공 결과는 기존 출처 규칙을 다시 검사한 뒤 읽기 전용으로 복원합니다. 새 환경 변수나 DB 마이그레이션은 없습니다.

배포나 서버 재시작만으로 미채점 답안을 다시 채점하지 않습니다. 저장된 답안·풀이·attemptId·요청 키를 보존하며, recovery가 허용하는 경우에만 같은 키·본문으로 명시적으로 재제출합니다. 기존 v4 실패 기록은 초기화하지 않습니다. uncertain 또는 만료 running 기록이 있는 세션은 v5에서도 신규 호출을 차단하며, 운영자 확인 절차를 우회하지 않습니다. 실제 유료 API 재검증은 별도 승인 대상입니다.

미로그인 401, CSRF 누락·오류 403, 타인/없는/잘못된 ID 404,
입력·요청 키 오류 422, JSON 파싱 오류 400입니다. 오류 본문은 기존 code·message와 선택적 recovery이며 비공개 답안을 담지 않습니다. 생성 관련 LearningException의 stage·diagnosticCode·retryAllowed·action을 그대로 전달합니다. CitationRules 길이 위반은 EVIDENCE_QUOTE_TOO_SHORT/TOO_LONG, 출처 개수/중복 근거는 CITATION_CARDINALITY_INVALID 등 안전한 코드로 구분합니다. review_required/limit_reached에서는 로딩과 자동 재전송을 종료하세요.
정상 결과는 기존 V9 테이블에 저장합니다. 마이그레이션 추가·기존 SQL 변경은 없습니다.

## 재설명·해설 연결

POST /sessions/{sessionId}/problems/{problemId}/reteach는 attemptId·expectedVersion과 요청 키로 B 재설명을 시작합니다.
기존 B /sessions/{sessionId}/reteach 경로도 같은 C 연결 지점에서 신규 시작의 근거 버전을 검증합니다.
진행 중인 재설명 재시도·대화·복귀 검증에는 시작 당시 문항 버전과 달라진 B 버전을 잘못 비교하지 않습니다.
새 답안·해설 요청은 C 기록과 복귀 표시를 읽기 전에 B 회원 → 세션 잠금을 취득합니다.
재설명 복귀 소비와 재제출 저장을 같은 트랜잭션으로 처리하며, 동시 같은 키는 동일한 시도와 응답으로 수렴합니다.
다른 키의 중복 재제출은 거절하고 첫 독립 답안은 유지합니다.

POST /sessions/{sessionId}/problems/{problemId}/solution은 채점된 문항의 정답·해설을 공개하고 열람 시점과 문항 확정을 저장합니다.
동시 요청도 최초 열람 시점을 유지하며, 이후 새 답안·재설명은 허용하지 않습니다.
기존 V1~V9 SQL과 B HTTP 계약은 유지합니다.

## 리포트 생성·조회·확인

POST /api/v1/sessions/{id}/report는 모든 문항 완료 후 리포트를 저장하고 B를 report 단계로 전환합니다.
GET은 저장된 리포트를 조회합니다. POST /report/confirm은 학생의 확인을 기록하고 B 학습을 completed로 종료합니다.
확인 전에는 홈의 이어하기 대상이고, 종료 후에도 GET으로 조회할 수 있습니다.
판정 보류는 완료된 문항으로 진행할 수 있지만, 리포트에서 오답·독립 정답과 분리합니다.

생성·확인 POST는 재호출·완료 이후에도 1~128자의 Idempotency-Key가 필수입니다.
작업 종류·학습 ID·요청 본문을 B와 공유하는 키 공간에서 검증하고, 다른 작업의 키 재사용은 409입니다.
새 키로 이미 존재하는 리포트를 반환할 때도 성공 이력을 저장합니다.
같은 키·같은 요청은 당시 성공 응답을 복원합니다. 예를 들어 생성 키의 재전송은 확인 후에도 당시 ready 응답입니다.
최신 confirmed 상태는 GET으로 확인하세요. 확인 키의 재전송은 최초 confirmed_at을 유지합니다.
입력·C 저장·B 전환·성공 이력은 한 트랜잭션으로 처리하며 실패하면 모두 롤백합니다.

계산은 B 잠금 밖에서 준비하고, 저장은 B 회원 → 세션 잠금 아래에서 현재 버전·평가 완료·리포트 소유권을 재검증합니다.
기존 B 내부 전환 API도 유지합니다. C의 LearningCommands 콜백은 같은 DataSource·스레드에서 DB 작업만 수행해야 합니다.
새 C 명령은 같은 기존 요청 이력 테이블을 쓰되 작업 구분 지문과 C 응답을 저장합니다. 기존 B 응답·기존 행은 변경하지 않습니다.
V10은 리포트 테이블만 추가하며 V1~V9 SQL을 수정하지 않습니다.

## 홈·재학습

GET /api/v1/home은 현재 회원의 진행 중 학습 한 건과 최근 리포트 다섯 건을 반환합니다.
problem 단계의 resumePath는 POST /problems, report와 B 세션 조회 경로는 GET으로 사용합니다.

POST /api/v1/sessions/{originId}/relearn은 확인한 리포트에서 같은 자료·개념의 새 학습을 mode 단계로 만듭니다.
로그인·CSRF·Idempotency-Key가 필수이고, JSON problemId는 해당 리포트의 nextSteps에서 선택하거나 생략합니다.
다른 학습이 진행 중이면 409 ACTIVE_SESSION_EXISTS입니다. 사용자가 교체를 확인한 경우에만
replaceSessionId와 expectedVersion을 함께 전송하세요.

재학습은 B 일반 생성과 별도 작업 지문을 가집니다. 원본 학습·리포트·보완 항목·교체 요청을 모두 키에 연결합니다.
일반 생성 키를 재학습에 쓰거나, 재학습 키를 일반 생성·다른 리포트 작업에 쓰면 409입니다.
같은 키·같은 요청은 원래 새 학습과 연결 정보를 복원합니다. 이후 그 학습이 교체·종료돼도 새로 생성하지 않습니다.
B 생성·기존 학습 교체·C 연결·성공 이력은 한 트랜잭션이며, 어느 저장이라도 실패하면 함께 롤백합니다.
동시 같은 키는 한 학습으로 수렴하고, 다른 키는 기존 진행 중 학습의 교체 확인을 우회하지 못합니다.

V11은 원본·리포트·새 학습 연결 테이블만 추가합니다. 기존 V1~V10 SQL은 수정하지 않았습니다.
실제 AI 문항 생성·채점과 A의 파일 분석·목록 연동은 계속 별도 작업입니다.
