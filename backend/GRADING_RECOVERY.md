# 사용자가 확인 후 실행하는 동일 답안 재채점

채점 요청의 응답을 받기 전에 타임아웃이 발생하면 답안은 저장돼 있지만 Gemini의 처리 완료 여부는 알 수 없다. 이 기능은 운영자 승인 없이 사용자가 안내를 읽고 **동일 답안을 한 번 추가 채점**하도록 한다. 타임아웃 자체나 Google 처리 지연을 해결하는 기능은 아니다. 이전 호출도 처리됐을 수 있으므로 추가 AI 사용량이 발생할 가능성을 안내한다.

## 보존과 호출 제한

- 기존 `learning_ai_generation`의 uncertain/만료 running 행, 예약 기록, 성공 캐시와 원래 답안을 삭제·초기화·성공으로 덮어쓰지 않는다.
- 원래 생성 키에 연결한 별도의 동의·실행 기록과 새 생성 영수증을 추가한다. 원래 요청의 모델·프롬프트·출력 설정·본문 해시가 정확히 같아야 실행할 수 있다. 설정을 바꾸거나 새 답안·시도 ID를 만들어 보류를 우회하지 않는다.
- 원래 호출을 포함한 `GEMINI_MAX_ATTEMPTS`와 프로젝트 분당/일별·회원 일별 한도를 그대로 검사한다. 기본 시도 한도 2에서 기존 1회 + 추가 1회이며, 추가 호출은 검증 실패여도 소모된다. 기존 시도 수가 이미 한도에 도달했다면 재채점할 수 없다.
- 원래 생성 키당 실행 기록은 UNIQUE다. 여러 서버, 여러 동의 요청, 새로고침, 연속 클릭으로 추가 호출이 늘어나지 않는다. 실행 후 다시 타임아웃/잘못된 응답이면 더 재시도하지 않는다.
- C의 `ProblemGenerator`, `AnswerGrader`, v5 프롬프트·인용 규칙·correct/wrong/pending_review 판정은 변경하지 않는다. B 대화·문제 생성 전체에 대한 uncertain 자동 재시도 권한도 제공하지 않는다.

## API 및 화면 순서

[추가 OpenAPI 계약](api/grading-recovery.openapi.json). 기존 B 명세와 C 답안 제출 201 응답은 유지한다.

1. `GET /api/v1/sessions/{sessionId}/grading-recovery`: 회원 소유권을 확인하고 저장된 문제·답안·풀이·원래 Idempotency-Key와 상태를 반환한다. `Cache-Control: no-store`. 원문·기대 정답·해설·채점 기준·운영 비밀은 반환하지 않는다. AI 호출·예약·동의 기록 생성은 없다.
2. `retry_available`인 경우 **동일 답안 재채점** 버튼에서 “이전 요청이 이미 처리됐을 수 있고 추가 AI 사용량이 발생할 수 있음”을 알린다. 취소하면 아무 요청도 보내지 않는다.
3. 확인한 회원만 CSRF 토큰과 함께 `POST .../grading-recovery/consent`에 `{"attemptId":"저장된 UUID","acceptDuplicateCall":true}`를 보낸다. 15분 유효한 `authorizationId`를 반환한다. 유효한 중복 동의는 같은 ID를 반환한다. 동의만으로 AI를 호출하지 않는다.
4. 기존 `POST /api/v1/sessions/{sessionId}/problems/{problemId}/attempts`로 **조회한 답안·풀이를 공백까지 그대로**, **원래 Idempotency-Key**와 함께 보낸다. `X-Teachmi-Recovery-Authorization` 헤더에 동의 ID를 전달한다. C가 저장된 동일 시도 ID를 재사용한다. 쿠키·CSRF·소유권 검사는 그대로 적용된다.
5. 공통 Gemini 파이프라인에서 정확한 요청 해시·세션 버전·근거·최신 미채점 시도·동의 만료·남은 사용량을 검증한 뒤 별도 실행 영수증을 한 번 예약한다. 사용자 입력 헤더 자체는 권한이 아니며 서버의 동의·소유권 검사를 통과해야 한다.
6. AI 응답을 기존 출처/스키마/도메인 검사로 검증하고 새 성공 캐시에 저장한 후 C가 원래 답안에 실제 판정을 저장한다. 원본 원장 행은 그대로 남는다. **성공 캐시와 C의 판정 저장이 모두 완료된 경우에만** 파생 뷰 `unresolved_ai_generation`이 원본 보류를 더 이상 진행 차단 대상으로 세지 않는다.

| 상태 | 화면/실행 규칙 |
| --- | --- |
| `none` | 복구할 미채점 답안 없음. 기존 학습 흐름 |
| `retry_available` | 저장 답안 읽기 전용. 사용자 확인 후 1회 재채점 가능. 남은 프로젝트 사용량은 실행 직전 다시 검사 |
| `running` | 정적 진행 안내와 수동 저장 상태 확인. 자동 POST/무한 폴링 없음 |
| `result_available` | AI 성공 캐시는 있으나 C 판정 저장이 아직 안 됨. 사용자 선택으로 동일 요청을 보내 캐시에서 복원하며 AI를 새로 호출하지 않음 |
| `completed` | 원래 답안의 판정 저장 완료. 동일 요청의 기존 성공 응답을 복원. 추가 AI 호출 없음 |
| `exhausted` | 추가 호출 소모. 답안 보존·추가 요청 차단·지원 안내 |
| `review_required` | 조건 불충족/기록 확인 필요. GET 확인만 제공하고 일반 생성 재전송 금지 |

`AI_RECOVERY_NOT_AUTHORIZED`(409)는 동의 만료·다른 소유자·다른 요청 해시·설정/근거 변경 등으로 실행할 수 없음을 뜻한다. `AI_RECOVERY_CONSUMED`(409)는 이미 추가 실행을 예약했음을 뜻한다. 429 사용량/시도 한도와 502/503의 기존 `recovery` 계약을 유지한다. 동일 동의로 502·503을 자동 재시도하지 않는다. CSRF 사전 거절 403 후 토큰 갱신은 같은 키·본문·헤더로만 재전송한다.

과거 원장은 특정 시도 ID 메타데이터가 없다. 따라서 동일 회원/세션에 미해결 영수증이 정확히 하나이고 최신 미채점 답안의 근거가 유효한 경우에만 동의 후보를 제공한다. 최종 실행은 현재 C 요청의 **정확한 생성 해시와 원래 키의 일치**를 다시 요구한다. 과거 B 호출이나 다른 모델/출력 설정에 대한 동의는 채점 호출을 허용하지 않는다. 이 경우 임의 설정 변경으로 재시도하지 않는다.

## 설정·배포·운영

- TEACHMi 기본 호출 한도는 분당 20회·전체 UTC 하루 500회·회원 UTC 하루 100회로 상향한다. 이미 저장된 호출 횟수는 초기화하지 않는다. 명시한 기존 환경 변수는 우선하므로, 실제 서버에서 예전 값이 설정돼 있다면 승인된 배포 때 함께 조정하고 시작 로그의 `Gemini quotas`로 확인한다. Google 프로젝트의 RPM/TPM/RPD나 요금제는 이 변경으로 늘어나지 않으며, Google 429·서비스 지연·40초 타임아웃을 해결한다고 보장하지 않는다.

- `GEMINI_USER_GRADING_RECOVERY_ENABLED=true`가 기본이며, `GEMINI_ENABLED=true`일 때만 새 사용자 동의/실행을 허용한다. 긴급 차단은 전자만 false로 설정한다. 새로운 동의/추가 호출이 차단되며 기존 성공 캐시·완료 답안 읽기 복원은 유지된다.
- Flyway V15는 새 감사 테이블 두 개와 파생 뷰만 추가한다. V1~V14 체크섬과 기존 데이터는 변경하지 않는다. 별도 마이그레이션 계정을 쓴다면 앱 계정에 새 테이블 SELECT/INSERT 및 뷰/기존 참조 테이블 SELECT 권한이 필요하다. PUBLIC 권한이나 SECURITY DEFINER 함수는 제공하지 않는다.
- 백엔드 V15 적용과 정상 기동을 먼저 검증한 뒤 프론트엔드를 적용한다. 새 GET이 실패하면 화면은 생성 버튼을 잠그고 수동 상태 확인을 제공한다. 백엔드보다 프론트를 먼저 배포하지 않는다.
- 실 운영자는 원래 uncertain 행만 세어 미복구 건수로 오인하지 않는다. `unresolved_ai_generation`, 추가 실행·성공 캐시, 원래 답안의 `judgement`/`graded_at`을 함께 대조한다. 동의 기록에는 회원·원래 키·시도·근거 버전·정책 버전·동의 시각·만료가 남고 실행 기록에는 별도 키가 남는다. 원문/답안/AI 응답 전문을 로그·공개 이슈에 올리지 않는다.
- 추가 호출도 불확실하면 두 영수증을 모두 보존하고 Google 프로젝트 사용량/요청 지표와 시간대를 대조한다. 클라이언트 타임아웃만으로 Google 처리 완료/미처리 또는 과금 여부를 확정하지 않는다. DB 상태 수동 변경이나 계속된 재시작으로 보류를 지우지 않는다.

## 검증 범위

합성 자료·가짜 전송기·격리 PostgreSQL에서 실제 A 인증/자료, B 세션/공통 원장, C 채점 API를 사용한다. 동의와 GET의 호출 0회, 정확한 본문/키/시도 보존, 세 가지 실제 판정 보존, 만료·CSRF·타인·변경 요청 차단, 동시 클릭 1회, 사용량·논리 시도 한도, 502/503 재실패 차단, 캐시 성공과 C 저장 사이 복원, 원본 원장 행 전체 불변을 검증한다. 실제 Google 성공률·유료 호출은 별도 승인 시험이며 이 변경에서는 실행하지 않는다.
